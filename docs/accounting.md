# Accounting constraints

The bridge must stop accepting traffic when client state or accounting is unavailable or uncertain. There is currently no integrated meter or enforcement; the read adapter requires explicit bridge usage before authorizing a client.

The [sing-box V2Ray API](https://sing-box.sagernet.org/configuration/experimental/v2ray-api/) requires a build with V2Ray API support. Its counters are process-local; a [documented reload issue](https://github.com/SagerNet/sing-box/issues/4059) reports loss of uncollected usage when the service reloads. Reading cumulative counters without reset avoids losing a sample if a collector crashes between reading and persisting it, but cannot recover traffic lost when sing-box itself crashes or reloads. Restart and reload must therefore invalidate meter certainty and fail closed until reconciled; a collector alone cannot promise exact accounting.

In the inspected 3x-ui source, `/panel/api/clients/updateTraffic/{email}` overwrites local counters, so read-modify-write would race concurrent Xray accounting and resets. `/panel/api/inbounds/pushClientTraffics` accepts idempotent absolute totals, but its global overlay takes the larger per-direction value rather than adding independent sources; it ignores stale overlays after 24 hours. It cannot safely represent bridge plus independent Xray usage merely by pushing the bridge total. Any integration must explicitly handle all sources, reset/renewal epochs, disappearing counters, idempotent retries, concurrent edits, and stale state. Until that behavior is proven with real 3x-ui and sing-box tests, no user should be enabled by this project.

`CounterLedger` now persists cumulative samples transactionally. Repeating a sample is idempotent; missing samples invalidate authorization, while counter regression or an unclean process-generation change requires reconciliation. Reads use a consistent SQLite snapshot. Closing an epoch requires a final sample and a trusted coordinator's confirmation that connections have drained. The ledger is not connected to a sing-box collector or panel synchronization yet; its guarantees depend on unique process epochs and verified draining.

`collector.read_counters` uses grpcurl against a loopback-only sing-box V2Ray StatsService endpoint, with `reset=false`. Supply the official matching `stats.proto` and a complete roster of configured, metered users; sing-box does not create a user's counters until it sees traffic, so absent counters are zero only under that configuration invariant. `collect` verifies a coordinator-supplied process epoch before and after reading and invalidates authorization on failure. This adapter has unit coverage but has not yet been verified against a live StatsService. The trusted process-generation source, meter-enabled sing-box build, and drained-reload coordinator remain required integration work.

`Panel.push_global_totals` now exposes the panel's authenticated absolute global-traffic push. Its inputs must already be the aggregate the panel should display, not an independent source to add. Repeating an absolute payload does not intentionally increment counters. This method alone does not solve concurrent Xray sources, renewal/reset epochs or runtime enforcement.

The isolated 3x-ui v3.11.0 integration test has verified login, client reads, repeated absolute traffic pushes without double counting, and an over-quota authorization result. This verifies the adapter and overlay semantics, not termination of live sing-box sessions. The custom sing-box image builds v1.14.4 at commit `c005f35300ce76427dc285481ec5695f5b179cd2` with `with_quic,with_v2ray_api`; the official image lacks the latter feature.

`process.docker_epoch` derives a meter epoch from a full immutable container ID and its Docker start timestamp, and rejects stopped, paused or restarting containers. The real-meter test now uses this source before and after sampling rather than a constant callback. This detects container restart/replacement, not an in-process sing-box reload; arbitrary SIGHUP/reload remains forbidden until the coordinator can drain traffic and finalize the old epoch.

The real sing-box v1.14.4 integration run `41418654779` passed a local VLESS transfer, gRPC collection and repeated cumulative-snapshot persistence. `sync_bridge_usage` now connects fresh ledger totals to the panel overlay for management-only panels: it requires disabled panel inbounds, pushes only explicitly managed users, rereads identity and totals, and invalidates ledger authorization on inconsistency. This function has unit coverage only. It does not handle panel renewal/reset epochs or terminate running bridge sessions; do not enable it as a production authorization service yet.
