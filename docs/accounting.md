# Accounting and admission constraints

`CounterLedger` stores cumulative per-user uplink/downlink counters in SQLite. Repeating a snapshot is idempotent. Authorization requires a fresh complete sample (30-second default maximum age). Counter regression, an unclean process epoch change, or missing/failed collection disables authorization. A unique process epoch is required. Normal shutdown finalizes it only after counted I/O is frozen and a trusted final snapshot is validated; hard crashes still leave the epoch unconfirmed.

The custom bridge image pins sing-box v1.14.4 commit `c005f35300ce76427dc285481ec5695f5b179cd2`, built with `with_quic,with_v2ray_api`; the official image lacks the latter feature. `collector.read_counters` invokes grpcurl over loopback with `reset=false` and the runtime service alias `v2ray.core.app.stats.command.StatsService`. The complete configured metered-user roster is required: counters absent before first traffic count as zero only under this invariant. Collection verifies the Docker process epoch both before and after sampling.

`process.docker_epoch` derives the epoch from the full immutable container ID and Docker start timestamp. Stopped, paused and restarting containers are rejected. This detects container restarts/replacements, but not arbitrary in-process SIGHUP/reload. Such reloads are forbidden: sing-box counters are process-local, and a [reported reload issue](https://github.com/SagerNet/sing-box/issues/4059) describes loss of uncollected traffic. Crashes can also lose usage since the last sample; exact recovery is not claimed.

## 3x-ui bridge-only synchronization

All panel inbounds must be disabled. Managed clients retain their panel UUID, subscription ID, enable flag, quota and expiry. Independent Xray traffic and concurrent sources are unsupported. The panel's `pushClientTraffics` endpoint accepts idempotent absolute totals; its per-direction overlay takes a maximum rather than summing independent sources and expires after 24 hours. The controller must therefore keep refreshing the overlay and preserve the aggregate it represents.

`sync_bridge_usage` requires fresh ledger totals for each managed user, refuses a panel total or direction above the local ledger, pushes absolute totals, rereads the panel, and checks identity and exact total before authorizing. Failures invalidate local authorization. Existing panel usage above a fresh zero ledger requires reconciliation; it must not be silently overwritten. Renewal/reset epochs, concurrent administrative edits, independent sources and reconciliation tooling remain unimplemented.

## Runtime enforcement

`LeaseCoordinator.tick` compares the complete current 3x-ui roster, collects usage, synchronizes the panel, checks the exact runtime identity set, rechecks the process epoch, then renews a ten-second lease. Its loop runs every five seconds. Added, removed, revoked, expired, identity-changed or over-quota users stop the current generation and remove its lease. The service finalizes that generation and opens a new one with the eligible roster. An edit is observed on the next check, not instantaneously; currently running users on the old generation are cut over only after the old generation ends.

The bridge image's `run` entrypoint requires `BRIDGE_RUN_ID` and `/run/vgb/lease.json`. The supervisor rejects missing, malformed, expired or different-generation leases and terminates the child process group when authorization expires. Leases use atomic writes and a maximum lifetime of 30 seconds; controller and guard must share the same Linux monotonic clock. Diagnostics (`check`, `version`, `format`) do not require a lease. The supervisor cannot protect a process outside container-level cleanup if the supervisor itself is killed.

`subscription_http` uses an HMAC of the panel email, UUID and subscription ID, requires fresh authorization on every request and checks expiry again after rendering. It binds loopback, disables URL logging and caching, and requires an external HTTPS endpoint for deployment. Withdrawing a subscription alone does not revoke cached credentials; the bridge supervisor provides runtime revocation.

## Verified evidence and remaining deployment work

- [41424458637](https://github.com/chengamki-tech/vpngate-bridge/actions/runs/41424458637): real local VLESS traffic, gRPC collection, idempotent persistence, real 3x-ui synchronization, coordinator renewal, higher-panel-total revocation and bridge container shutdown.
- [41441487326](https://github.com/chengamki-tech/vpngate-bridge/actions/runs/41441487326): authenticated subscription download/import, verified VLESS/WS/TLS and Hysteria2 clients through a real qualified KR VPNGate exit, panel accounting, blocking traffic after OpenVPN termination, subscription refusal and bridge shutdown on accounting inconsistency.

These isolated short tests do not establish production readiness. The live stack grants temporary bootstrap leases only with all proxy listeners on runner loopback. A public deployment must authenticate and reconcile before admission, handle drained final snapshots and configuration changes, recover orphan containers and uncertain ledger epochs, and provision public subscription HTTPS. Those startup/recovery paths are still missing.

`runtime.open_bridge` builds a roster from currently eligible panel clients, validates the sing-box configuration under the final UID/capability restrictions, then synchronizes a zero-raw-counter preflight epoch before exposing listeners. That preflight can close cleanly because no bridge exists yet. It persists a new unclean run intent before Docker starts, so a lost Docker response cannot be retried as zero usage. It pins the run UUID to the observed Docker incarnation before renewing its lease. The same persisted signing key deterministically derives Hysteria2 credentials with a separate HMAC domain. The roster is fixed only for one generation; `service.serve` keeps the subscription endpoint alive while it reconciles roster changes through new generations.

The launcher cannot mark an epoch clean after a hard crash: there is no final drained snapshot for a killed controller, and a subsequent start remains blocked until reconciliation. For a normal shutdown, `runtime.open_bridge` stops the bridge, checks that its incarnation did not change, and only closes the epoch clean after `final_stats.read_final` validates the run-UUID snapshot for the full roster; without a valid snapshot the epoch stays unconfirmed, the ledger is not deleted, and `quiesced=True` is not faked. [Run 41574382327](https://github.com/chengamki-tech/vpngate-bridge/actions/runs/41574382327) passed this path through two live generations, both TLS clients, HTTPS subscription, cumulative accounting and cleanup. [Run 41575307782](https://github.com/chengamki-tech/vpngate-bridge/actions/runs/41575307782) passed a live added-client roster change through the same generation lifecycle.
